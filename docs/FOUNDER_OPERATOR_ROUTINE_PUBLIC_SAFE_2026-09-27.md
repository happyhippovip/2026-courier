# Founder / Operator Routine — Public-Safe — 2026-09-27

Status: DURABLE OPERATING ROUTINE
Purpose: reduce repeated coordination, protect sleep/time, and keep Courier/company work moving from durable state.

## Rule 1 — Do not make the founder the message bus

Normal worker results should go to durable result files and the Harvester.

The founder should normally be interrupted only for:
- real money decisions
- real safety decisions
- permission/credential decisions
- unresolved ownership/truth conflicts
- final PRE_CODEX gate
- Codex blocking defect / physical-run readiness
- RUN_1 / RUN_2 result
- pilot decision signal

## Rule 2 — One permanent prompt

After /clear, new provider session, new terminal, or context loss:
use:
ops/ai/COURIER_PERMANENT_MASTER_WORKER_PROMPT.txt

Do not rebuild the project plan manually.

## Rule 3 — Sleep-friendly work

Before leaving the machines unattended:
- persist queue/results/checkpoints
- keep source writer ownership singular
- keep heavy jobs bounded
- use durable tasks rather than open-ended discovery
- stop paid/API workers when they become TRUE_IDLE
- do not rely on the founder typing "continue"

Overnight target may be up to 10 hours when host resources are safe.

## Rule 4 — Context hygiene

When a session becomes slow/stale:
CHECKPOINT
-> save exact next action
-> /clear or new session
-> reload master control + current queue
-> continue

Do not retain obsolete branches/logs/chat history in active context merely because they existed earlier.

## Rule 5 — Daily operating sequence

1. Read master control plane.
2. Read current queue pointer.
3. Harvest returned results.
4. Check current Critical Path gate.
5. Admit only dependency-safe work.
6. Keep one mutable writer per scope.
7. Prefer deterministic tests over model opinion.
8. Stop idle analysis.
9. Persist end-of-session handoff.
10. Leave exact next action for the next session.

## Rule 6 — Weekly company review

Review:
- Core gate evidence
- pilot readiness / pilot metrics
- provider cost and waste
- setup/support burden
- wall duplicate rate
- restart/recovery failures
- security/update risks
- customer signal
- next smallest causal business/engineering blocker

Do not add features merely because capacity is free.

## Rule 7 — Cost discipline

Track cost as an operating metric, not as a reason to waste already-paid capacity.

Spend when the work:
- closes a real blocker
- produces required evidence
- reduces risk
- shortens human coordination
- prepares a real pilot/release step

Stop when work becomes:
- duplicate
- unchanged
- speculative
- idle
- non-goal

## Rule 8 — Health / personal privacy boundary

This public repository is not the place for private life records, medical information, private financial details, credentials, account identifiers, or private family/customer data.

Only public-safe operating preferences and company/project rules belong here.

Any deeper personal-life planning must be stored privately and intentionally, not inferred or invented by Courier.
