# Courier Symphony — Company Expansion Roadmap

Date: 2026-09-20  
Status: strategic working roadmap

## Positionierung

Nicht "noch ein KI-Chat".

Courier Symphony soll die **Goal-to-Done Operating Layer** sein:

```
Ziel
-> Planung
-> Agenten + Tools + Wissen
-> Arbeit
-> Prüfung
-> Ergebnis
-> Archiv / Wiederverwendung
```

## Geschäftsmodell

Ziel: sehr niedrige Eintrittshürde.

Mögliche Ebenen:
- kostenloser Basis-Chat / Knowledge-Zugriff mit Limits;
- günstige Agenten-Credits für einfache Aufgaben;
- bezahlte Goal-to-Done-Aufträge;
- Business-Workspace;
- Gilde/Expertenvermittlung;
- Content-/Website-Pakete;
- API / white-label später.

Kostenkontrolle:
- retrieval first,
- kleine Modelle,
- Caching,
- lokale Worker,
- asynchrone Batch-Arbeit,
- teure Modelle nur für schwierige Schritte.

## Moat / langfristiger Wert

Nicht nur "welches Modell wir benutzen".

Schutz/Vorsprung entsteht durch:
- Knowledge Graph / Community-Wissen,
- bestätigte Workflows,
- Task-/Result-Daten,
- Agentenfähigkeiten,
- Qualitätsmetriken,
- Integrationen,
- eigene Brand/Community,
- produktive Pipeline-Erfahrung.

## Nächste sinnvolle Reihenfolge

1. Backup + Cloud-Recovery absichern.
2. Bestehende Cloud sauber inventarisieren.
3. Courier Core stabilisieren.
4. Ein kleines echtes Goal-to-Done Vertical shippen.
5. Courier AI + Knowledge als günstige Support-Schicht.
6. Website Factory als erstes verkaufbares Vertical.
7. Content Studio aus bestehender Pipeline produktisieren.
8. Gilde zunächst klein/kuratiert starten.
9. Analytics/Kosten pro Auftrag messen.
10. Erst danach stark skalieren.

## Erstes Vertical

Empfehlung für Verkauf:
**"Sag uns dein Geschäftsziel — Courier baut dein digitales Startpaket."**

Beispiel:
- Bäcker
- Pizzeria
- lokaler Dienstleister
- Creator
- kleines Online-Angebot

Lieferumfang:
- Positionierung
- Name/Claim-Ideen
- Website-Struktur
- Texte
- FAQ
- Content-Plan
- einfache Website
- Übergabeordner
- optional Content-Pipeline-Anschluss

So ist der Kundennutzen sofort verständlich und messbar.
