# Courier Symphony Project Agent Rules

## Read order
1. ops/ai/GATE_STATE_CURRENT.md
2. ops/ai/FOUNDER_WORKING_PROTOCOL_CURRENT.md
3. ops/ai/ENDGAME_SLOT_ROUTER_CURRENT.md
4. .agents/memory/COURIER_SYMPHONY_CURRENT.md
5. only the minimum source/evidence needed for the assigned lane

## Truth hierarchy
Executable source/runtime/git identity beats stale prose.
Actual physical evidence beats preparation.
Unchanged accepted evidence is reused, not repeated.
UNKNOWN never becomes PASS by narration.

## Ownership
- exactly one application-source writer;
- exactly one Physical Mac Owner;
- read-only workers never self-authorize either role;
- foreign processes/ports/PIDs/PGIDs are never killed or taken over;
- failed physical evidence is sticky;
- Product Shell remains locked until positive real pilot evidence.

## Candidate binding
Never start physical proof unless the exact reviewed candidate is durable and:
FINAL_SHA == REMOTE_SHA == LOCAL_SHA == BOUND_SHA.

Orphaned/local-only/unpublished commits are not physical candidates until explicitly adopted and rebound.

## Current endgame
candidate-state reconciliation -> one writer if required -> changed-byte convergence -> exact Mac binding -> RUN_1 -> RUN_2 -> Core Freeze -> minimum real pilot -> Product Shell only after positive pilot.

## Work discipline
Do not redo Ledger absent RETEST_TRIGGER, PRE_CODEX, runner rediscovery, acceptance-harness false-proof finding, or unchanged completed lanes.
Do not invent work to consume quota.
If one subcase blocks, checkpoint it and continue independent legal work.
If every useful item is owner-gated, record WAITING_FOR / NEXT_OWNER / NEXT_ACTION and emit NO_REAL_WORK.
Do not use model watch/sleep loops.

## Long-running autonomy
A prompt cannot reliably force a turn to stay alive for hours.
Long-running work is provided by an external supervisor that relaunches bounded headless turns after real state changes.

## Physical proof
RUN_1 requires exact-once A, real effect, exact result/artifact identity, task-owned expected hash, independent verification, reconcile, NEXT_READY, automatic B continuation, zero human relay, zero failed executions.
RUN_2 requires accepted RUN_1 PASS, controlled restart, A persistence/no reexecution/count one, stale identity rejection, legitimate B continuation, zero human relay.
PREP_ONLY != PROVEN. TEST PASS != PHYSICAL PASS.
