# Pilot Page (`/pilot`)

Grounded in plan §§14–20. Pilot comes before Product Shell; first pilots are accompanied/manual — the page must say so.

## Page structure

1. Headline: "First pilots: bring one real goal, keep working the next day."
2. What we test (exactly one sentence, plan §16): "Courier brings you the next day exactly where you stopped." + plain list of what we measure: your handoffs saved, restart behavior, whether you came back the next day, setup and support effort, provider cost.
3. What you get: accompanied setup, manual onboarding (measured, not hidden — plan §15), a visible board (Arbeitet / Braucht dich / Fertig), a proof card per finished piece, agreed data/permission scope in writing.
4. What we ask: one confirmed goal, a baseline interview (15 min), payment of the pilot fee (experiment — see pricing), permission to measure the metrics above.
5. Fit filter — good fit: work that survives overnight (research, content ops, long task queues); pain with lost context, copy/paste, re-explaining. NOT a fit (say so openly): anything needing a finished app, marketplace, billing platform, enterprise admin, or guarantees we haven't proven (register C1–C7, C11).
6. Apply → form (below).

## WAITLIST / PILOT_FORM_FIELDS (minimal, privacy-lean)

Required: name, email, one-goal description (free text, max 500 chars), where work currently breaks (select: lost context / copy-paste / re-explaining / session breaks / handoffs / other), data sensitivity (select: public / internal / confidential — confidential routes to a scoping call, never auto-accepted), availability for baseline interview (select).
Optional: tools in use (free text), monthly spend on AI tools (ranges, for pricing experiment), "may we contact you about the pilot" (checkbox, unchecked default).
Forbidden on the form: passwords, API keys, payment data, full data-room uploads. Payment details only after written pilot agreement, via the agreed payment path — never via this form (plan §19; no payment data in repo/forms).

## MANUAL_ONBOARDING_FLOW (v1, accompanied — plan §15)

1. Application review (fit + sensitivity triage, ≤3 days response).
2. 15-min baseline interview (current workflow, pain, success criterion) → written baseline note.
3. Goal Contract confirmation (one page: outcome, scope, non-scope, constraints, acceptance criteria, evidence class, human/money/safety gates) — signed by reply, plan §5.
4. Accompanied setup (screen-share; time measured as SETUP_MINUTES_PER_PILOT; manual steps disclosed, not disguised).
5. Pilot run (agreed duration) → proof cards delivered per finished piece.
6. Next-day check: did you continue from Courier's state? (NDR signal.)
7. Exit interview + metrics (HIPG, RSR where observable, NDR, PAYMENT_YES/NO, effort, cost).

## INSTALL_PREREQUISITES (pilot honesty box)

"No installer yet — setup is accompanied and manual. You need: a machine or cloud VM we can both access for setup, accounts/keys YOU own and enter yourself (we never ask for your passwords or keys by mail/form), and ~30 minutes for the baseline + setup call. An automatic installer is explicitly not a pilot prerequisite (plan §15) and will not be promised on this page."

## PRICING_EXPERIMENT_COPY (register C8 — labeled experiment)

"Pilot pricing is an experiment, not a price list. Orientation from our plan: a setup/pilot fee in the range of 49–99 €. The actual fee, what it covers, and what we learn from it (payment yes/no, effort, recurrence, support load) will be agreed in writing before the pilot starts. No subscriptions, no billing platform, no hidden costs — there is nothing to subscribe to yet."
